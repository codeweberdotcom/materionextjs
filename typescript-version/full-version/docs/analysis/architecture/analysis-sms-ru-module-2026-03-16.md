## 🏗️ Архитектура модуля

```
SMSService (abstract)          ← определяет контракт
  └─ SMSRuProvider              ← реализация через node-sms-ru
       └─ sendCode()            ← отправка кода верификации
       └─ getBalance()          ← проверка баланса
       └─ validatePhone()       ← валидация +7XXXXXXXXXX
       └─ sendTest()            ← тестовая отправка

SMSRuSettingsService (singleton)
  └─ getSettings()              ← читает sms-ru-settings.json (кеш 5 мин)
  └─ updateSettings()           ← пишет sms-ru-settings.json

API Routes:
  GET  /api/settings/sms-ru         → getSettings (apiKey masked)
  PUT  /api/settings/sms-ru         → updateSettings
  GET  /api/settings/sms-ru/balance → getBalance()
  POST /api/settings/sms-ru/test    → sendTest()

Использование:
  POST /api/register → sendCode() при requirePhoneVerification=true
```

**Позитивное:**
- Правильная абстракция: `SMSService` (abstract class) позволяет добавлять новых провайдеров
- Используется `withApiHandler` — соответствует стандарту проекта
- Тестовый режим (`testMode`) реализован правильно — логирует, не отправляет
- Неблокирующий вызов в регистрации — ошибка SMS не прерывает flow
- API-ключ маскируется в GET-ответе (`***provided***`)
- Кеш настроек (5 мин) снижает нагрузку на I/O

## 🔍 Результаты анализа

### Найденные проблемы:

#### 1. **КРИТИЧЕСКАЯ: API-ключ хранится в plaintext, файл не в .gitignore**
   - Описание: `sms-ru-settings.json` содержит реальный API-ключ SMS.ru в незашифрованном виде. Файл находится в корне проекта и **не включён в `.gitignore`** (в git status отображается как `??`). При случайном `git add .` секрет попадёт в репозиторий.
   - Сравнение: `ServiceConfiguration` (redis, postgres, smtp и др.) использует **AES-256-GCM шифрование** и хранит данные в **БД**, а не в файле.
   - Влияние: **Критическое** — утечка API-ключа, возможность несанкционированной отправки SMS за счёт владельца
   - Приоритет: **Критический**

#### 2. **ВЫСОКИЙ: Неправильный модуль прав доступа**
   - Описание: Все три API-роута используют `permission: 'smtpManagement.read'` / `'smtpManagement.update'`. SMS — отдельный сервис, не имеющий отношения к SMTP.
   - Последствие: Пользователь с правом `smtpManagement.read` автоматически получает доступ к SMS-настройкам, и наоборот. Нет возможности разграничить доступ.
   - Правильно: `'smsManagement.read'` / `'smsManagement.update'`
   - Влияние: **Высокое** — нарушение принципа least privilege
   - Приоритет: **Высокий**

#### 3. **ВЫСОКИЙ: Отсутствуют Prometheus метрики**
   - Описание: Отправка SMS — операция с прямыми финансовыми последствиями. Нет счётчиков: `sms_sent_total`, `sms_failed_total`, `sms_cost_total`.
   - Сравнение: В проекте метрики добавлены для авторизации, регистрации, bulk-операций и rate-limit.
   - Влияние: **Высокое** — нет мониторинга расходов и сбоев
   - Приоритет: **Высокий**

#### 4. **ВЫСОКИЙ: Нет audit event при сохранении настроек**
   - Описание: PUT `/api/settings/sms-ru` обновляет критичные настройки (смена API-ключа, выключение testMode), но не пишет событие в EventService.
   - Сравнение: В проекте CRUD-операции над настройками пишут события `settings.updated` / `settings.created`.
   - Влияние: **Высокое** — нет истории изменений конфигурации
   - Приоритет: **Высокий**

#### 5. **СРЕДНИЙ: UI — кнопка "Проверить баланс" заблокирована без прав update**
   - Описание: В `SMSRuSettings` (view) кнопка баланса использует `disabled={!canUpdate || ...}`, хотя API-эндпоинт требует лишь `smtpManagement.read`. Пользователь с правом только на чтение не может проверить баланс.
   - Файл: [src/views/apps/settings/sms-ru/index.tsx:298](src/views/apps/settings/sms-ru/index.tsx#L298)
   - Влияние: **Среднее** — UX-ошибка
   - Приоритет: **Средний**

#### 6. **СРЕДНИЙ: Телефонная валидация — только Россия**
   - Описание: `validatePhone()` проверяет только `/^\+7\d{10}$/`. Проект поддерживает 4 языка (en, fr, ar, ru) и internationalization. Международные пользователи не смогут получить SMS-верификацию.
   - Влияние: **Среднее** — блокирует международные номера
   - Приоритет: **Средний**

#### 7. **СРЕДНИЙ: UI без i18n**
   - Описание: Все строки в `SMSRuSettings` захардкожены на русском языке. Проект использует систему переводов (`useTranslation`/словари). `dictionary` импортирован, но нигде не используется.
   - Влияние: **Среднее** — несоответствие стандарту проекта
   - Приоритет: **Средний**

#### 8. **СРЕДНИЙ: Множественные `(result as any)` касты**
   - Описание: В `SMSRuProvider.ts` 8 мест с `(result as any)`. Это указывает на то, что типы библиотеки `node-sms-ru` не покрывают фактический ответ API.
   - Файл: [src/services/sms/providers/SMSRuProvider.ts](src/services/sms/providers/SMSRuProvider.ts)
   - Влияние: **Среднее** — потенциальные runtime-ошибки, отключён TypeScript
   - Приоритет: **Средний**

#### 9. **НИЗКИЙ: useEffect — отсутствует `loadSettings` в зависимостях**
   - Описание: `useEffect(() => { if (canRead) loadSettings() }, [canRead])` — `loadSettings` не включена в массив зависимостей (react-hooks/exhaustive-deps).
   - Файл: [src/views/apps/settings/sms-ru/index.tsx:56](src/views/apps/settings/sms-ru/index.tsx#L56)
   - Влияние: **Низкое** — предупреждение линтера, потенциальный stale closure
   - Приоритет: **Низкий**

#### 10. **НИЗКИЙ: Нет тестов**
   - Описание: Для `SMSRuProvider`, `SMSRuSettingsService` и API-роутов нет ни unit-, ни integration-тестов.
   - Влияние: **Низкое** — риск регрессий при изменениях
   - Приоритет: **Низкий**

## 📝 Выводы

Модуль SMS.ru **функционально работает** и правильно интегрирован в flow регистрации. Архитектура с абстрактным классом `SMSService` — хорошая основа для будущего расширения.

**Главная критическая проблема** — хранение API-ключа в незашифрованном файле без `.gitignore` защиты. Это должно быть исправлено немедленно, до следующего коммита.

Остальные проблемы — несоответствия стандартам проекта (permissions, метрики, события, i18n), которые рекомендуется исправить в рамках доработки модуля.

**Следующие шаги:**
1. Немедленно: добавить `sms-ru-settings.json` в `.gitignore`
2. Создать план доработки модуля SMS.ru с устранением найденных проблем
3. Определить стратегию хранения настроек (env vs DB)
