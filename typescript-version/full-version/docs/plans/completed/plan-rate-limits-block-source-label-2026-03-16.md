# План: Исправление метки источника автоматических блокировок

**Дата:** 2026-03-16
**Статус:** Ожидает одобрения
**Приоритет:** Средний
**Анализ:** `docs/analysis/ui-ux/analysis-rate-limits-block-source-label-2026-03-16.md`

---

## Что меняется

В `RateLimitEngine.ts` при формировании admin-записи для `UserBlock` — проверять `blockedBy`:
- `blockedBy === 'system'` → `source: 'state'` → UI покажет **"Авто"**
- `blockedBy` = ID пользователя/строка → `source: 'manual'` → UI покажет **"Ручная"**

---

## Файлы для изменения

| Файл | Изменение |
|---|---|
| `src/lib/rate-limit/services/RateLimitEngine.ts` | Строка ~755: условное назначение source |

**Только 1 файл, 1 строка.**

---

## Изменение кода

```typescript
// Было (строка ~755):
source: 'manual',

// Станет:
source: block.blockedBy === 'system' ? 'state' : 'manual',
```

## Обратная совместимость

- Все ручные блоки (от администратора) продолжают отображаться как "Ручная"
- Только автоматические блоки (`blockedBy: 'system'`) начнут отображаться как "Авто"
- API, удаление блоков, фильтрация — не затронуты

## Что НЕ будет затронуто

- Логика создания блоков
- Redis keys
- UserBlock/RateLimitState таблицы
- Фильтр по источнику в UI (уже работает для обоих)
